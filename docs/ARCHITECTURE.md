# 仓库、升级和发行约定

本文件记录已确认的目标架构。实际完成情况以 [STATUS.md](STATUS.md) 和 Comet 验收为准。

## 文件归属

| 位置 | 职责 |
| --- | --- |
| `lonefisher/fishgram`，`main` | 定制 AGENTS、工具、配方、指南、正式规格、CI、发行记录、源码 gitlink |
| `lonefisher/tdesktop`，`custom/main` | 官方历史、定制源码、生产测试、品牌、更新器 |
| 忽略的本机目录 | API 身份、登录数据、Runtime、锁、原始输出、备份、缓存、实例、打包暂存 |

子模块固定具体提交。源码先推，父指针后推；不存在跨仓库原子提交。源码 AGENTS 始终与对应官方基线一致。公开源码从官方基线与审查的定制提交建立，本机文档分支仅留私有备份。

## 构建与升级

`fishgram.json` 固定官方 tag/提交、MSVC 14.44、SDK 26100、Qt 5.15.19、平台、渠道、修订号和更新启用状态。显示版本 `7.2.9-r8`；更新版本是 `(官方整数版本 << 32) | 修订号` 的十进制字符串。每个公开包使用新修订号，Beta 转稳定也必须递增。

计划使用标准 GitHub Actions；先真实验证无缓存构建，再验证缓存构建。PR 不接触发行身份或签名密钥；候选从审查的固定提交在受保护环境中构建。只缓存可信依赖，键绑定平台、工具链与准备脚本；不缓存客户端编译目录或 API 配置。免费资源不足必须报告测量瓶颈，不自动购买或用本机成功替代云端结果。

每天检查官方稳定发行，通过只授权这两个仓库的 GitHub App 建立关联候选 PR。冲突停止并创建去重记录，不覆盖定制实现。先合并源码 PR，再更新父指针并重新检查。机器人不能绕过分支检查、发布或推动客户端更新。

## 更新信任与安装

发行附件位于 GitHub Releases；稳定/Beta 索引和根签名密钥清单位于 GitHub Pages。客户端只使用 FishGram 来源和 v2 签名包，拒绝官方 HTTP/MTP 发现及 RSA 回退。索引只发现候选，包签名、目标、渠道、完整版本决定安装资格。

根密钥离线加密备份。发行密钥有效期一年，在到期前45天提醒；受保护发布环境仅在人工批准后开放。客户端验证根签名清单版本、续期及吊销，拒绝降级清单和吊销密钥。根密钥丢失或受损通过手动重新安装恢复。

默认检查并下载稳定版，保留关闭开关；Beta 必须主动选择。下载后提示下次重启安装，不自动退出。按独立工作目录单实例，同一安装目录仅一个事务。安装前校验签名、平台、渠道、版本、大小、哈希、解包路径，禁止路径穿越及账户数据载荷；检查空间、权限和进程退出，程序备份与事务记录支持失败恢复。网络或校验失败继续当前版本并显示原因。

## 发行与恢复

固定顺序：云端构建 → 下载同一候选实测 → 哈希及验收记录 → 人工批准签名 → 发布附件 → 验证公开下载 → 最后更新渠道索引。候选验收后不重新编译；签名产物须对应验收的程序哈希。已发布标签和附件不得替换。

每次提供 ZIP、签名更新包、校验、递归对应源码与构建脚本、构建清单、许可、说明及限制。普通替换失败恢复旧程序，保留含当前在内最近三个程序版本。跨官方版本前正常退出并建立账户数据快照，默认保留最近两份；新版已迁移数据后，恢复数据需明确选择。

问题版本先停止索引推广，保留问题记录，再以更大版本发布修复。在线更新只向前；手动回退使用独立工具。首版不增加遥测或向官方上报崩溃，问题模板不请求账户数据或 API 凭据。

## 首版门槛

原搜索八项全验收、真实云端候选实测、Windows 11 干净环境运行，以及同基线/跨基线更新、禁用、多实例、中断、损坏/错误签名/官方/旧包、路径穿越、空间不足、文件占用和恢复全部通过。r7仅为本机历史交付。任何未执行或失败的检查不得写成通过。

# 目标
落实已批准 FishGram 方案的产品身份、免费标准 GitHub Actions 云端构建、受保护候选、人工发行及官方升级候选机器人。首版 Windows 11 x64 便携；不在门槛通过前发行二进制。

# 范围
用户计划 §2 全文对应本 change 的固定配方、版本、升级与 CI；§4 产品身份、源码与许可发行、人工流程对应身份和发行验收；§5③对应全部验收。§3更新安全交由独立 fishgram-auto-update，原搜索八项交由 restricted-global-search，均是公开发行前置门槛，不替代、不放宽。

# 决策
父 main、源 custom/main，两仓库标签绑定同一输入；官方基线加每包新的修订号，Beta转稳定也递增。MSVC14.44/SDK26100/Qt5.15.19固定且自动定位。标准 runner 免费优先，无缓存首次验证后验证缓存；不自动付费。GitHub App只授权这两仓库，每日检查官方稳定，关联PR、去重失败记录，先源后父。PR无发行凭据，产品候选从审查提交在人工批准环境构建；依赖缓存绑定可信配方，不缓存客户端/API目录。固定云端候选验收后签名，不重编译，附件公开下载验证后最后发索引。

# 非目标
不发布未经完整验收的安装包，不创建付费 runner，不自动合并或发布，不改变搜索性能目标、不处理官方访问限制，不用本机构建充当云端成功。

# 验收示例
- A1：产品名称、独立图标、应用ID、默认数据目录统一FishGram，自己的API身份，非官方说明、基本功能与广告保留，无新增遥测/官方崩溃上报。
- A2：源码和子模块一致性、五组生产helper、脚本及测试身份编译对全部PR运行；外部PR无法访问发行API或签名密钥。
- A3：标准Windows runner从固定父/源/递归依赖提交无缓存实际完成准备与客户端构建，记录空间、耗时、工具链和程序哈希；如失败报告实际瓶颈，不算本机成功。
- A4：可信依赖缓存按平台/工具链/准备内容精确绑定，实际缓存构建通过且不缓存或上传API配置/客户端编译目录。
- A5：受保护环境和分支检查有效，产品候选从已审查输入使用FishGram身份；所有发行前置门槛未通过时没有公开二进制或更新索引。
- A6：首次和重复官方检查、冲突、CI失败均正确；机器人使用仅两仓库GitHub App创建关联PR/去重记录，不能绕过检查、自动发布或更新客户端。
- A7：清单包含父/源/递归提交、工具链、平台渠道完整版本及产物SHA256；对应源码与构建脚本、GPLv3/OpenSSL例外/依赖许可完整。
- A8：实测同一云端候选后不重编译，人工签名对应程序哈希，发布附件并公开下载核验后最后更新索引；已发布标签附件不覆盖。

# 待解决问题
产品API身份和GitHub App注册/安装需要真实账户状态核实；若缺少，准备可审查配置，记录外部阻塞，继续免费构建等独立工作。用户已批准完整方案并要求实施，沿用确认。

# 约束与不变量
API身份、签名私钥和账户数据不进Git或公开日志。免费优先；不抢用户前台，不覆盖标签附件，不放宽原搜索标准，缺失证据不算完成。

# 验证预期
独立只读Verifier覆盖A1-A8；检查两仓库和权限，实际无缓存及缓存云端运行、机器人首次/重复/冲突/失败，实际候选哈希与发行次序。外部凭据及未完成前置门槛写成阻塞，不伪造通过。

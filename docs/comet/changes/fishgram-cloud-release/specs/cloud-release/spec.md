# FishGram 云端与产品发行

本规格按用户已确认方案 §2、§4、§5③实施。验收A1-A8与brief一致，失败、未执行、外部条件缺失不计通过。

## 输入及版本
配方固定官方 tag/commit、源码gitlink、递归依赖、MSVC14.44、SDK26100、Qt5.15.19、Windows11x64、稳定/Beta及修订。显示7.2.9-r8；完整更新整数采用十进制字符串。每个公开包、Beta转稳定均新修订。父main、源custom/main；源码先推/合并，父指针后推/合并。两层发行标签不覆盖。

## CI与权限
全部PR跑生产helper、源码/子模块一致性、脚本及测试身份编译，无发行凭据。标准GitHub Actions拆分依赖准备和客户端构建，无缓存首测、缓存复测均有真实记录。只缓存可信依赖，键包含平台/工具链/准备脚本哈希；不缓存API配置或客户端目录。受保护环境的已审查固定提交才使用产品API身份。人工验收、签名、发布；机器人没有发布能力。免费资源不足报告实际空间/耗时等瓶颈，不购买或本机代跑冒充云端。

## 官方升级
每日通过限制两仓库的GitHub App检查官方稳定。新tag建源升级分支、尝试合并、建立关联源/父PR。冲突停止，去重记录目标/文件。重复检测不重复PR；CI失败保持候选不推广。人工解决和审查工具链；先合源再更新父gitlink重新验收后合父。App不得绕过保护，不得发布或更新索引。

## 身份及交付
名称、独立图标、应用ID、默认数据目录FishGram；使用自己的Telegram API应用。明确非官方，保留基本功能/广告；不新增遥测或向官方发送定制崩溃。首版Windows11x64便携。

候选云端构建→下载同包实测→保存哈希及完整验收→人工批准签名→附件→公开下载核验→索引最后。候选验收后不重编译；签名包对应验收程序SHA。每版提供完整ZIP、v2更新包、校验、递归源码/脚本、构建清单、GPLv3/OpenSSL例外/依赖许可、说明和限制。自己的更新签名与未采购的Authenticode用途分开说明。

## 公开门槛
原搜索八项全部通过、实际云端候选实测、自动更新与程序/数据恢复通过后首发。r7保留本机历史。即使CI或helper成功也不得公开未经完整验收的客户端。
